Revisión local de estructura, rutas, autenticación, configuración, fuentes de datos, manejo de errores, documentación y compilación. No se accedió ni modificó Supabase remoto.

- Login, actualización de cuenta y cierre de sesión utilizan Supabase Auth.
- `.env` no está versionado y `.env.example` no contiene credenciales reales.

- La página pública dispone de respaldo JSON y timeout de conexión.

- La medición local usa una lista cerrada de campos y no admite datos personales.

## Hallazgos

### Prioridad alta

- `supabase/schema.sql` crea políticas administrativas amplias como paso inicial. La seguridad final depende de ejecutar `002_restringir_administradores_rls.sql`. El orden obligatorio quedó documentado, pero debe verificarse manualmente en Supabase.

### Prioridad media

- `Admin.jsx`, `BakerySite.jsx`, `global.css` y `admin.css` concentran responsabilidades y están altamente compactados. Una separación futura mejoraría mantenimiento, pero no se realizó automáticamente por riesgo de regresión.
- No existen pruebas automatizadas de autenticación, fallback, CRUD ni filtros comerciales.
- Hay tres capas de datos que pueden divergir: JSON local, valores predeterminados en JavaScript y Supabase. Supabase tiene prioridad cuando responde; JSON es respaldo.
- La analítica y CRM actuales son locales al navegador. No ofrecen métricas globales ni sincronización entre dispositivos.

### Prioridad baja

- Existen componentes y páginas iniciales que no participan en las rutas actuales. Se conservaron para evitar eliminaciones con impacto desconocido.
- Se mantienen JPEG originales junto con WebP para compatibilidad, lo que aumenta el tamaño del repositorio aunque reduzca transferencia web.

## Cambios seguros aplicados
